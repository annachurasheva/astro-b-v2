 ====варианты к обсуждению до привлечения КОДЕРА ====

Вот несколько вариантов задания для LLM (под связку «Думающий + Писарь»), чтобы она только подставила твои данные в шаблон и ничего лишнего не придумывала. Выбери тот, который ближе к твоей ситуации.

---

## Вариант 1 — самый строгий (лучше всего для нестабильной LLM)

> Ты — исполнитель по шаблону. Твоя единственная задача: взять предоставленный шаблон и заменить в нём все шаблонные данные на мои реальные данные.  
> 
> Правила:
> - Не меняй структуру шаблона ни на символ (отступы, заголовки, порядок секций — всё должно остаться как есть).
> - Не добавляй новых разделов, комментариев, вступлений, выводов и пояснений.
> - Не перефразируй формулировки шаблона — меняй только конкретные значения (названия, пути, имена, URL).
> - Если какое-то поле у меня не заполнено — оставь там оригинальный текст шаблона.
> 
> Образец структуры данных бери строго с сайта-образца (ссылка ниже). Не используй другие источники.
> 
> В конце выдай только итоговый результат — готовый файл/текст. Никаких «вот что я сделал», «я проверил» и т.п.
> 
> Шаблон:  
> ```
> [вставь сюда свой шаблон целиком]
> ```
> Мои данные:  
> ```
> [перечисли свои данные чётко по полям]
> ```
> Образец структуры (источник): [ссылка на сайт-образец]

---

## Вариант 2 — под README / документацию (если ты редактировал README.md)

> Твоя роль: «Чистый наполнитель» — только подстановка значений в готовый шаблон без изменений структуры.  
> Задача: обновить шаблон README.md, заменив все плейсхолдеры на мои актуальные данные.  
> 
> Требования:
> - Сохраняй 100% структуру, заголовки и подзаголовки как в шаблоне.
> - Меняй только конкретные строки-значения (пути, имена репозиториев, ссылки, версии).
> - Не трогай примеры кода и скриншоты — только текстовые поля.
> - Не генерируй новые разделы («Рекомендации», «Полезные ссылки» и т.д.).
> - Не объясняй свои действия. Выдай только итоговый Markdown-текст.
> 
> Шаблон README:  
> ```
> [шаблон]
> ```
> Мои актуальные данные:  
> - Репозиторий: [путь/URL]  
> - Ветка по умолчанию: [название]  
> - Пути к папкам: [список]  
> - Remote-ы: [список]  
> - Другие значения: [перечень]  
> Источник структуры: [ссылка на образец]

## Вариант 3 — для JSON/конфига (если речь про `package.json`, конфиги и т.п.)

> Роль: «Строгий маппер по шаблону».  
> Задача: сформировать итоговый JSON/конфиг строго по предоставленному шаблону, подставив мои данные.  
> 
> Ограничения:
> - Структура (ключи, вложенность, порядок ключей) — без изменений.
> - Никаких дополнительных полей, комментариев или пояснений.
> - Если значение не предоставлено — оставляй оригинальное значение из шаблона.
> - Источник правил структуры — сайт-образец по ссылке.
> - На выходе — только чистый JSON (без markdown-блоков, без текста «вот результат»).
> 
> Шаблон:  
> ```json
> [шаблон JSON]
> ```
> Мои данные для подстановки:  
> [список пар ключ-значение]  
> Источник структуры: [ссылка]

## Что обязательно добавить, если у тебя «Думающий + Писарь» как два этапа

Если ты явно разделяешь этапы, можно написать так:

> Этап 1 (Думающий): сопоставь каждое поле из моих данных с соответствующим местом в шаблоне и в образце структуры. Составь таблицу соответствий «поле шаблона → моё значение». Не меняй шаблон.  
> Этап 2 (Писарь): на основе этой таблицы сформируй итоговый файл, строго сохраняя структуру шаблона и заменяя только значения. Никаких дополнений и пояснений. На выходе — только итоговый контент.
